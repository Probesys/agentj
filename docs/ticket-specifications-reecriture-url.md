# Ticket - URL Rewriting and Protection

## Objective

Protect HTTP(S) links in incoming emails by routing them through an AgentJ
redirector. Clicks are logged and the security policy is evaluated at click
time using the latest available data.

The processing flow must remain safe:

```text
authenticate -> analyze -> rewrite -> sign DKIM -> seal ARC -> deliver
```

V1 applies a single configuration to all recipients of a message. Supporting
distinct policies by group is a later enhancement because it requires splitting
an SMTP transaction before rewriting.

## V1

### Authentication Milter before Amavis

- Add a milter before Amavis to evaluate SPF, DKIM, and DMARC on the received
  message, before any header or body transformation.
- Add an `Authentication-Results` header generated by AgentJ with its own
  `authserv-id`, immediately after the first `Received` header.
- Preserve pre-existing `Authentication-Results` headers. They must not be
  removed or rewritten because they may be covered by an existing DKIM
  signature.
- Disable native DKIM verification in Amavis and SpamAssassin when this profile
  is enabled.
- Use a SpamAssassin plugin that reads only the first AgentJ
  `Authentication-Results` header inserted by the milter.
- Restrict Amavis input to the internal Postfix path that has applied the
  authentication milter.
- Record `pass`, `fail`, `none`, `temperror`, and `permerror` results for each
  authentication mechanism.

### Rewriting on Receipt

- Process incoming messages after Amavis through a dedicated content milter.
- Rewrite `http` and `https` URLs in `text/plain` and `text/html` parts.
- Use a tolerant HTML parser; do not modify scripts, comments, or the `mailto:`,
  `tel:`, `cid:`, and `data:` schemes.
- Do not modify messages without eligible URLs.
- Do not rewrite encrypted messages or S/MIME- or PGP-signed messages.
- Do not nest already valid AgentJ wrappers.
- Apply one global policy, `rewrite` or `no_rewrite`, to all recipients in the
  transaction.

### Wrapper and Redirection

- Generate a versioned, signed wrapper bound to the organization and destination
  URL. Unsigned wrappers are prohibited.
- Use the organization's primary redirect domain. Previous domains may remain
  active as aliases to preserve existing links.
- Provide a database-backed link for wrappers that exceed the chosen maximum
  length.
- Accept only valid HTTP(S) destinations; reject unknown redirect hosts and any
  modified destination.
- On click, apply `pass`, `warning`, or `block` according to the current policy.
- Return `302` for `pass`, display a confirmation for `warning`, and do not
  automatically redirect for `block`.
- Publish click metrics asynchronously and without blocking.

### Integrity and Operations

- Sign the final message with an AgentJ-controlled DKIM key, then add ARC to
  that signed version.
- If a required component is unavailable, defer the message: no partially
  signed version may be delivered.
- Bound MIME processing: message size, parts, URLs, output growth, concurrency,
  and spool space. Expose metrics and structured logs.
- Resolve known POC blockers before activation: malformed milter frames,
  multipart reconstruction, HTML entities, and memory limits.

### Acceptance Criteria

- DKIM verification completes before AgentJ adds its
  `Authentication-Results` header.
- Existing `Authentication-Results` headers remain unchanged, while
  SpamAssassin uses only the AgentJ result inserted by the milter.
- A sender-provided `Authentication-Results`, including one with a forged
  AgentJ `authserv-id`, is never used in place of the milter result.
- An SPF, DKIM, or DMARC evaluation error does not block delivery; its status
  is retained in the AgentJ result and exposed through logs and metrics.
- Every message accepted by Amavis has crossed the authentication milter.
- An eligible link is rewritten exactly once and opens its destination after
  signature validation.
- An unchanged message, an untargeted attachment, and a signed or encrypted
  message are preserved.
- DKIM and ARC are valid for the bytes actually delivered.
- A rewriter, signer, or sealer failure triggers a retry with no loss,
  duplication, or partial delivery.
- The MIME corpus and load test validate 100 KB, 5 MB, and 40 MB sizes, along
  with the defined limits and backpressure.

## Enhancements

### Per-Group Policies and SMTP Splitting

- Resolve the effective policy for each recipient from AgentJ rules (global,
  group, user, and exceptions).
- Group recipients that have the same rewriting result.
- Split the SMTP transaction before the milter when at least two body variants
  are required; create only one variant for each distinct result.
- Pass an internal policy context to the milter and remove any sender-injected
  policy header.
- Make fan-out durable and idempotent to prevent loss and duplication after a
  partial success or lost SMTP response.
- Preserve envelope parameters, including DSN and SMTPUTF8, and bound the
  router's global spool.

### Functional Enhancements

- Add rewriting and click rules by domain, subdomain, path, and exact URL, with
  AgentJ's standard priorities.
- Add allowlists, blocklists, categories, and local reputation for click-time
  decisions, without network access in the normal path.
- Import and maintain URL classification sources (categories, phishing, and
  malware) in versioned local snapshots.
- Add incoming ARC validation and support absent, valid, invalid, and malformed
  chain cases.
- Support third-party service wrappers, individual tracking, and URLs from
  attachments or QR codes according to product requirements.
